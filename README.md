# agent-cost

Cost and time tracking for Claude Code sessions. It records every session, including built-in and Herdr sub-agents,
so the whole agent tree's cost, start time and duration are shown in the status line, stored as a JSON file per main
session and shown on a live page served by a local server (or exported as a static HTML report).

- Total cost of the main session plus built-in sub-agents plus Herdr sub-agents, recursively.
- Start time and duration in the status line; sub-agents get a `[sub:<role> d<depth>]` label.
- One JSON file per main session (`roots/<root>.json`).
- Live report page on `http://127.0.0.1:<port>/` that updates by itself while it is open.

Requirements: `python3` ≥ 3.10 on `PATH`. No dependencies.

## Install

From GitHub:

```
/plugin marketplace add dmytromykhailiuk/agent-cost
/plugin install agent-cost@agent-cost
```

Local checkout (development):

```
/plugin marketplace add /path/to/agent-cost
/plugin install agent-cost@agent-cost
```

The hooks (SessionStart, UserPromptSubmit, Stop, SubagentStop, SessionEnd) are installed with the plugin and record
sessions automatically.

## Status line setup

```
/agent-cost setup            # prints the diff for ~/.claude/statusline/dashboard.js
/agent-cost setup --apply    # applies it (after you approved the diff)
/agent-cost doctor           # checks hooks, dashboard patch, pricing
```

It adds its own line under line 1: `session 14:02 · 18m · Σ $4.21 · main $2.91 · agents $1.30 (3)`. In a sub-agent: `[sub:reviewer d1]` next to the profile label and `session … · Σ … · self $0.40`.

## Commands

`<skill_dir>/bin/agent-cost <command>` (or `/agent-cost <command>` in Claude Code):

| Command | What it does |
|---|---|
| `serve [--session SID] [--port N] [--no-open] [--stop\|--status] [--foreground]` | Starts the live page server in the background (or reuses the running one), opens `http://127.0.0.1:<port>/#<sid>`, prints a summary line and the URL as the last line. |
| `report [--session SID\|--latest\|--all] [--out PATH] [--no-open]` | Static export: writes a self-contained HTML file, opens it, prints a summary line and the absolute path as the last line. |
| `list [--limit N] [--json] [--all]` | Recorded main sessions inside `visible_roots` (`--all` adds the hidden ones). |
| `show [SID\|--latest] [--json]` | One session's agent tree. |
| `scan [--since 30d] [--config-dir DIR]` | Backfills history from transcripts. |
| `doctor [--dashboard PATH]` | Diagnoses the installation. |
| `setup [--apply] [--dashboard PATH]` | Shows or applies the dashboard patch. |
| `version [--json]` | Plugin version. |
| `hook <event>`, `statusline [--json]` | Internal; called by Claude Code. |

In Claude Code, `/agent-cost` runs `serve --session <current session>` directly (one command, no sub-agent: the page
is generated by code) and replies with only the URL, so cost data never lands in the main context.

## Live page

`agent-cost serve` runs a stdlib `ThreadingHTTPServer` bound to `127.0.0.1` only.

- Port 47821 by default, or a free port when it is taken. `state/server.json` holds `{pid, port, started_at, version}`
  and the log goes to `state/server.log`.
- A second `serve` finds the healthy running server (pid alive and `/api/health` answers with the same pid) and only
  opens the URL. A server from another plugin version is stopped and started again.
- It stops by itself after 2 h without requests; `serve --stop` stops it now, `serve --status` prints its URL.
- A background thread rescans transcripts changed since the last pass every ~10 s (the incremental transcript cache
  makes this cheap) and rewrites the affected `roots/*.json`. Errors go to `server.log`; requests are never blocked.

Endpoints: `/` (the page), `/api/data` (the same payload `report` embeds, each root with a `hidden` flag),
`/api/data?since=<token>` (only roots changed since that token plus `removed` root ids, `incremental: true`; an unknown
token or changed config returns the full payload), `/api/version` (`{version, token, count}`; `?roots=1` adds the
per-root versions), `/api/health`. A root's version is its `roots/<sid>.json` mtime and size, and `write_root` skips
rewrites that would only change `generated_at`, so an idle root never shows up in a delta.

The page loads the full payload once, then polls `/api/version` every ~3 s while the tab is visible. When the token
changes it fetches `/api/data?since=<its token>` (typically one live root, ~40 KB instead of ~1.7 MB), merges it and
re-renders, keeping the selected session and agent, filters, open folders and scroll position. The top bar shows
`live · updated hh:mm:ss`, or `offline` when the server can't be reached. The same `report.html` works as a static
file: with embedded data it never polls.

## Linking and headless sessions

`scan` (and the server's refresher) links a session to its parent from, in order of trust:

1. Herdr launch records (`~/.local/state/herdr-agents/launches/<sid>.json`, `env.HERDR_PARENT_SESSION_ID`), which
   exist while a Herdr child is alive.
2. `[herdr-agent] … session=<sid>` lines in the parent's transcript and in the parent's background task output files
   (`/private/tmp/claude-<uid>/<project>/<parent sid>/tasks/*.output`).
3. The child's `agent-name` matching a Herdr id spawned by the parent.
4. agent-verify-loop state (`$VERIFY_STATE_DIR`, `~/.local/state/agent-verify-loop`, legacy `claude-verify`):
   `runs/*/context.json` (run → main session, per-attempt agent session ids, `retro_agent`), `ledger.jsonl` and
   `sessions/*.events.jsonl` (run → main session, `agent_done`/`retro_done` session ids) and `sessions/*.json`
   (`parent_session_id` recorded by vloop's hooks). A verifier whose run is gone is linked through its prompt
   (`Your task file is …/runs/<run>/attempt-N/<role>.prompt.md` or `…/retro/…`); a run missing from all vloop state is
   resolved by finding the interactive session active at the run's start whose transcript mentions the run id (cached in
   `cache/vloop-runs.json`). Codex runs are ignored.
5. For headless runs and named Herdr agents only: a working directory inside another session's scratchpad
   (`/private/tmp/claude-<uid>/<project>/<parent sid>/…`), else a scratchpad path of another session in the first
   prompt. Interactive sessions are never linked this way.

Live headless verifiers started by vloop carry `VLOOP_PARENT_SESSION_ID`/`VLOOP_GUARD_ROLE`, so their hooks record the
link at once. verify-loop triage runs `claude -p --no-session-persistence` and leaves no transcript; its cost
(`attempt-N/triage.json` `agent.cost_usd`, else the ledger's `cost_usd.triage`) becomes one synthetic headless session
`vloop-triage-<run_id>` under the run's main session.

Every non-main session gets a `purpose`: `verify:triage`, `verify:review`, `verify:qa`, `verify:retro` (vloop role, or
Herdr ids `verify-review-*`, `verify-qa-*`, `vault-retro-*`), `vault` (`vault-*` agents, vault `Operation:` prompts),
`harness` (cwd inside `~/.claude` or `$CLAUDE_CONFIG_DIR`) or `task`. The timeline and the agent panel show it as a
small badge. agent-vault's vault-keeper/vault-reviewer and anything run through the built-in Agent tool are built-in
sub-agents (`subagents/` in the parent transcript) and are already part of the parent's cost.

A link is written into the session record, so it survives the launch record or task file being deleted. A session that
was first recorded as its own root and later gets a parent is moved under that parent with its whole subtree.

## Visible roots

A root is shown only when its cwd is inside one of `visible_roots` (config, default `["~/Desktop"]`; `[]` shows
everything). Roots outside, mostly agent runs that could not be linked to their main session, stay on disk but are
hidden from `list` (`--all` shows them) and from the sidebar, where a "Show hidden (N)" checkbox at the bottom reveals
them together with unlinked headless runs. They are not user sessions, so "Spend over time" leaves them out unless they
are shown; unlinked headless runs inside `visible_roots` always count.

## Data layout

State dir: `$AGENT_COST_STATE_DIR`, else `${XDG_STATE_HOME:-~/.local/state}/agent-cost/`.

```
roots/<root_session_id>.json   aggregated tree per main session
sessions/<root>/               raw per-session records
cache/                         transcript aggregates
reports/                       generated HTML
server.json, server.log        the running live server
```

Config: `~/.config/agent-cost/config.json` (or `$AGENT_COST_CONFIG`) with `project_roots` (folders used to group
sessions in the report) and `visible_roots` (see above), e.g.
`{"visible_roots": ["~/Desktop", "~/work"], "project_roots": ["~/Desktop/projects"]}`.
Without it the report uses whichever of `~/projects`, `~/Desktop/projects`, `~/Desktop/npm-packages`, `~/code`,
`~/src`, `~/dev`, `~/work` and `~/.claude` exist; sessions elsewhere are grouped under "Other".

`roots/<root>.json` (schema 1):

```
schema, generated_at, root_session_id
totals: cost_usd, own_cost_usd, agents_cost_usd, sessions, builtin_agents, by_model
sessions[]: session_id, kind (main|herdr|headless), parent_session_id, depth, herdr_id, role, purpose, headless, entrypoint,
            cwd, model, effort, started_at, last_activity_at, ended_at, duration_s, state, task, result_excerpt, transcript_path,
            cost: {effective_usd, reported_usd, reported_source, estimated_usd, by_model},
            subtree_cost_usd, builtin_agents[]
```

## Cost model

- `effective = max(reported, estimated)`.
- Reported cost comes from Claude Code (status line payload or cost state) and includes built-in sub-agents and hidden
  calls.
- Estimated cost is computed from transcript token usage with `skills/agent-cost/config/pricing.json` (copied from
  agent-verify-loop). A model missing from the table has no USD (shown as n/a).

## Limitations

- A Herdr child started in the background is linked only while its launch record or the parent's task output file
  exists (the system may clean `/private/tmp`), or when the parent later read that output into its transcript.
- Headless runs outside a scratchpad with no vloop record have no parent marker and stay separate (hidden) roots.
- A vloop verifier whose run is in no vloop state and in no main transcript stays a separate root.
- `/clear` starts a new root.
- SessionEnd may not fire when a Herdr tab closes; the Stop hook keeps the record complete.
- The pricing table drifts as prices change; update `config/pricing.json`.
